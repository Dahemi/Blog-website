--- ANALYSIS (captured 22 Sep 2026, before any fix) ---
Tested against GET /getUser/000000000000000000000000 — a real application
route, not "/" — because "/" doesn't exist in this app and falls through to
Express's own finalhandler module, which hardcodes Content-Security-Policy
and X-Content-Type-Options on its own 404/500 pages regardless of app
configuration. Testing a real route confirms the app itself has neither.

MISSING (all absent):
  Content-Security-Policy

PRESENT BUT SHOULD NOT BE:

Also note: Access-Control-Allow-Credentials is set on this response too,
because index.js:43-46 sets it outside the cors() origin check, on every
response unconditionally.

Separate minor bug noticed in passing (not V10, worth one line in the
report's root-cause discussion): GET /getUser/:userId crashes with
"Cannot destructure property 'password' of 'user' as it is null" when the
ID doesn't match a user — controllers/user.js does not check whether
User.findById() returned null before destructuring it.
